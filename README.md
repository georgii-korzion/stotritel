# Смотритель — монитор блотов в прайсе Fimex

Раз в 30 минут бот забирает прайс Fimex (xlsx), сравнивает его с прошлым и пишет в Telegram-группу о позициях, которые:

- **A. резко подешевели** — на 5 % и больше или на $100 и больше относительно прошлой цены;
- **B. выбились среди регионов** — стали дешевле ближайшего по цене другого флага на 5 % / $100 (пишет только при появлении разрыва и только если он возник из-за самой позиции).

Полное ТЗ — в задаче; здесь — как этим пользоваться.

## Работа с ботом на Railway

| Что нужно | Как |
|---|---|
| Посмотреть логи | `railway logs -n 100` (из папки проекта) |
| Обновить бота после правок | `railway up` из папки проекта |
| Остановить бота | `railway down` |
| Поменять настройки | дашборд Railway → проект `fimex-blot-monitor` → сервис `monitor` → **Variables**; после сохранения Railway сам перезапустит сервис |

Перед первым использованием команд сверяйтесь с `railway <команда> --help` — флаги CLI иногда меняются.

Что бот пишет в группу сам:

- алерты по позициям (по одному сообщению; если за цикл больше 15 — 15 самых сильных и одно сводное);
- «✅ Монитор запущен…» — один раз, при первом запуске с пустой базой;
- «⚠️ Fimex не отвечает: нет данных с ЧЧ:ММ» — после 3 неудачных циклов подряд, и «✅ Данные от Fimex снова идут» после восстановления;
- «⛔ Fimex отклонил токен» — на 401/403; бот переходит на попытки раз в 2 часа;
- «⚠️ Похоже, формат прайса Fimex изменился» — если файл перестал разбираться;
- «⏳ Токен Fimex истекает…» — за 14 дней до `exp` в токене;
- «💓 Жив: за сутки N циклов, K ошибок, M алертов» — раз в сутки в `DAILY_REPORT_HOUR` (по умолчанию 10:00 по Дубаю). **Если этой строки нет — бот, скорее всего, не работает**: смотрите логи.

## Ограничения запросов к Fimex (важно)

API Fimex перестаёт отвечать, если дёргать его часто. Поэтому:

- интервал — 30 минут, меньше 15 код не примет (`POLL_INTERVAL_MIN` ниже 15 поднимается до 15);
- время последней попытки хранится в `state.db`; после рестарта бот ждёт остаток интервала;
- при ошибках интервал удваивается (30 → 60 → 120), после 401/403 — 2 часа, `Retry-After` соблюдается;
- **работает только один экземпляр.** Когда бот живёт на Railway, на Mac ничего не запускать (`run` и живой `once`). Прогоны на файле (`once --file …`) запросов не делают — их можно.

## Команды

```bash
python -m fimex_monitor run                                   # боевой цикл (на Railway запускается сам)
python -m fimex_monitor once                                  # один живой цикл и выход
python -m fimex_monitor once --file samples/X.xlsx            # цикл на файле: без сети, сообщения в консоль, база сохраняется
python -m fimex_monitor once --file samples/X.xlsx --dry-run  # то же, но ничего не сохранять
python -m fimex_monitor chat-id                               # id чатов, где бот видел сообщения
python -m fimex_monitor send-test                             # тестовое сообщение в группу
```

База лежит в `DATA_DIR` (по умолчанию `data/`). Для проверок используйте отдельный каталог, чтобы не смешивать с боевой базой: `DATA_DIR=data-test python -m fimex_monitor …`.

Живой `once` откажется работать (код выхода 3), если с прошлой попытки в этом `DATA_DIR` прошло меньше интервала.

## Этапы из ТЗ — что запускать

**Этапы 0–1 (сверка с образцом, парсер).** Без сети:

```bash
python -m pytest tests/test_sample.py -v       # контрольные числа из раздела 4
python tools/inspect_pricelist.py samples/fimex-pricelist-20261007T205720Z.xlsx
```

`inspect_pricelist.py` печатает все контрольные числа, названия, которые встречаются на листе в двух блоках (5 штук на листе Samsung), и топ разрывов.

**Этап 3 (прогон без сети).**

```bash
python tools/make_stage3_sample.py samples/fimex-pricelist-20261007T205720Z.xlsx
#  → samples/stage3-fimex-pricelist-20261007T205720Z.xlsx: −3 %, −6 %, −$120 у позиции дороже $3000,
#    и падение < 5 %, после которого появляется разрыв; скрипт сам проверяет, что алертов ровно три
rm -rf data-stage3
DATA_DIR=data-stage3 python -m fimex_monitor once --file samples/fimex-pricelist-20261007T205720Z.xlsx          # стартовое сообщение
DATA_DIR=data-stage3 python -m fimex_monitor once --file samples/stage3-fimex-pricelist-20261007T205720Z.xlsx --dry-run  # три алерта
```

**Этап 4 (Telegram).** Создать бота в @BotFather, записать `TG_BOT_TOKEN` в `.env`, добавить бота в группу, написать в группе `/start@имя_бота`, затем:

```bash
python -m fimex_monitor chat-id     # взять id группы (отрицательный, у супергрупп начинается с -100) → TG_CHAT_ID в .env
python -m fimex_monitor send-test
```

**Этап 5 (один живой цикл на Mac).** Ровно один раз:

```bash
DATA_DIR=data-test python -m fimex_monitor once
python tools/compare_articles.py samples/fimex-pricelist-20261007T205720Z.xlsx data-test/raw/fimex-pricelist-*.xlsx
```

После этого на Mac живых запусков больше не делать.

**Этап 6 (Railway)** — по шагам из ТЗ: новый проект `fimex-blot-monitor` с сервисом `monitor`; **сначала** том `/app/data` и переменные (`DATA_DIR=/app/data`, `TZ=Asia/Dubai` и все ключи из `.env`), **потом** `railway up`. Проекты `courier-bot` и `cozy-blessing` не трогать. Домен сервису не нужен.

## Настройки

Все ключи — в `.env.example`. Основные:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `FIMEX_JWT` | — | токен Fimex |
| `FIMEX_SEND_APP_ACCESS` | 0 | 1 — отправлять заголовок `x-app-access` (`FIMEX_APP_ACCESS`), если без него начнутся 401/403 |
| `TG_BOT_TOKEN`, `TG_CHAT_ID`, `TG_THREAD_ID` | — | бот, группа, тема (необязательно) |
| `POLL_INTERVAL_MIN` | 30 | интервал; меньше 15 не принимается |
| `DROP_PCT` / `DROP_ABS_USD` | 5 / 100 | пороги правила A |
| `GAP_PCT` / `GAP_ABS_USD` | 5 / 100 | пороги правила B |
| `ETA_MAX_DAYS` | пусто | учитывать только предложения с ETA не дальше N дней; пусто — все |
| `MIN_PRICE_USD` | 0 | игнорировать предложения дешевле |
| `BASELINE_MAX_AGE_HOURS` | 24 | после скольких часов прошлая цена считается устаревшей |
| `ALERT_COOLDOWN_HOURS` | 12 | не повторять алерт по той же позиции, если цена не ниже уже присланной |
| `MAX_ALERTS_PER_CYCLE` | 15 | потолок отдельных сообщений за цикл |
| `DAILY_REPORT_HOUR` | 10 | час суточной сводки; пусто — выключить |
| `TZ` | Asia/Dubai | часовой пояс сообщений и «даты выгрузки» |
| `DATA_DIR` | data | где `state.db` и `raw/`; на Railway — `/app/data` (том) |

## Устройство

```
fimex_monitor/
  config.py   настройки из окружения; жёсткие пределы (15 мин, 120 мин, 14 дней)
  fetch.py    один GET к Fimex, проверка ответа, разбор exp из JWT
  parse.py    xlsx → список предложений; признаки смены формата
  rules.py    чистые функции: состояние + предложения → алерты (правила A и B)
  store.py    SQLite: positions, alerts, cycles, outbox, meta
  notify.py   тексты сообщений и отправка в Telegram (Bot API, без фреймворка)
  main.py     цикл, расписание с бэкоффом, служебные сообщения, команды
tools/        утилиты для этапов 0, 3 и 5 (без сети)
tests/        pytest, без сети; tests/test_sample.py — на образце из samples/
```

Состояние обновляется только после успешного разбора выгрузки. Алерт считается отправленным только после ответа Telegram; если отправка не удалась, позиция не сдвигается и алерт повторится в следующем цикле. Сырые xlsx лежат в `DATA_DIR/raw/` сутки.

Допущения раздела 12 ТЗ (только падение цены, ближайший регион для правила B, любой ETA, «второе предложение» в любом регионе, сравнение с прошлым циклом, количество не влияет, одинаковые названия на листе — один товар) собраны в `fimex_monitor/rules.py` и перечислены в его docstring.
